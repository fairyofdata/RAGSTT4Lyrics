# RAGSTT4Lyrics — うろ覚えの歌詞から J-POP を探す (Songfinder)

[English](README.md) · [한국어](README_kr.md) · [日本語](README_jp.md)

> 🏆 **韓国貿易協会 第47期 SCIT Master プロジェクト発表会 優秀賞（2位）。** 6人チームのプロジェクトURFITで受賞しました。
> 👤 このリポジトリは、URFITのうちペク・ジホン（Jiheon Baek）が一人で担当した音声認識・検索・推薦・Spotify連携モジュールです。2026年のリファクタリングと性能評価も一人で行いました。
> ℹ️ 最初はHugging Face Spaces上のプロトタイプで、その後AngularのフロントエンドとFastAPIのバックエンドに分けて作り直しました。

![URFITの画面](./Sample.png)

URFITは、音声認識を使ったAIプレイリスト作成コミュニティです。うろ覚えの歌詞を話すか入力すると、そのJ-POPの曲を見つけます。
- 音声はWhisperで歌詞を書き起こしてから検索します。そのため、歌詞のない鼻歌やメロディだけで探す機能ではありません。
- 既存の曲検索の二つの限界を解決するために企画しました。不正確な歌詞では見つからないこと、そして曲を見つけた後に続く体験がないことです。

URFITという名前には三つの意味を込めています。
>  * 韓国語：얼핏 듣다（ちらっと聞く）。ちらっと聞いた曲を見つけ、聴いて共有できる場
>  * 英語：Your (UR) Fit（Music Recognition & Recommendation）
>  * 日本語：運命のリズム、触れ合う意味の繋がり。

リポジトリ名 **RAGSTT4Lyrics**（旧名 `LLM_STT_Songfinder`、モジュール名 Songfinder）は処理の流れをそのまま表しています。音声を書き起こし（**STT**）、歌詞をベクトルで検索し（**R**etrieval）、見つかった曲の要約・タグを GPT に渡してプレイリストのタイトルと説明を書きます（**G**eneration）。曲を特定する段階そのものは、LLM を使わない埋め込み検索です。

## 🎵 主な機能

  * **うろ覚えの歌詞で曲を探す：** 不正確な歌詞を話しても入力しても曲を見つけます。どの程度見つかるかは下の「概要」にまとめました。
  * **似た曲の推薦：** 見つかった曲の歌詞、雰囲気、タグをもとに似た曲を3曲推薦します。
  * **Spotifyプレイリスト作成：** 推薦曲をSpotifyのプレイリストとして保存します。
  * **プレイリストのタイトルと説明の生成：** OpenAIのGPTモデルが曲の特徴からタイトルと説明を書きます。
  * **コミュニティ機能：** 検索した曲やプレイリストを他のユーザーと共有します。

## 🔍 概要

![Songfinderの構成と評価範囲](./docs/assets/architecture.png)

点線の枠で示した**曲の特定段階だけを切り出して定量評価**しました。数値は、索引済みの歌詞から作った合成クエリとTTS音声による値で、実際の利用時の精度ではありません。人の録音、歌唱、鼻歌は測定していません。

- **歌詞を入力した場合：** 1位正解率60.6%、上位10件以内76.2%。誤字には強く（79.8%）、前半しか覚えていない場合は弱いです（32.9%）。
- **歌詞を話した場合（アプリの設定）：** 日本語ネイティブの発音で47%、**韓国語なまりの発音で36%**、1行だけ話すと76%です。
- **原因は二つ**
  - Whisperが韓国語なまりの発音の35%を韓国語と判定し、ハングルで書き起こします。
  - 歌詞を1行単位で索引しているため、長く話すほど正解率が下がります。
- **改善（アプリに反映後に測定）**
  - Whisperが韓国語と判定した場合は、日本語として書き起こし直します。
  - 複数行のクエリは、行の長さに分けた断片の投票で曲を決めます。
  - その結果、韓国語なまりの発音は36% → 69%、ネイティブの5行は47% → 74%になりました。1行のクエリとテキスト検索の結果は以前と同じです。
- **その他の発見：** テキスト検索の要約分岐にあったインデックスのバグは修正済みです。次の二つは今後の課題です。
  - 「見つからない」の判定しきい値が、DBにない文の93%を通してしまいます。
  - 短すぎる歌詞の行が誤答を引き寄せます。

## 🛠 アーキテクチャと技術スタック

単一アプリケーションだったプロトタイプを、フロントエンドとバックエンドに分けました。

### 1. Frontend（Angular）
  * **Framework：** Angular 17（元のVanilla JS/HTMLから移植）
  * **Styling：** TailwindCSS、SCSS
  * **主な機能：** Spotify Web Playback SDKとの連携、マイク録音（MediaRecorder）と送信

### 2. Backend（FastAPI）
  * **Framework：** FastAPI（Python 3.10以上）
  * **AI/ML**
      * OpenAI **Whisper**：音声 → テキスト
      * **SentenceTransformer**（`paraphrase-multilingual-MiniLM-L12-v2`）+ **FAISS**：歌詞のベクトル類似度検索（`search.py`）
      * OpenAI **GPT-3.5-turbo**：プレイリストのタイトルと説明の生成
  * **主な機能：** Spotify OAuth認証、音声検索・テキスト検索API、CORS設定

## 🚀 ローカルでの実行方法

フロントエンドとバックエンドをそれぞれ起動します。

### 事前準備
1. Python 3.10以上（3.13以上では`audioop-lts`が追加で必要な場合があります）
2. Node.js 18以上とnpm
3. [Spotify Developer Dashboard](https://developer.spotify.com/dashboard)でアプリを作り、`Client ID`と`Client Secret`を取得
   * **Redirect URI：** `http://localhost:7860/callback`（httpsではなくhttp）
   * 開発モードのアプリは、登録したユーザーしかログインできません（2026年時点で最大5人）。
4. `.env`ファイルまたは環境変数：`OPENAI_API_KEY`、`SPOTIPY_CLIENT_ID`、`SPOTIPY_CLIENT_SECRET`、`SPOTIPY_REDIRECT_URI=http://localhost:7860/callback`
5. 歌詞データ：著作権の都合でこのリポジトリにはありません。`line_metadata.json`と`song_metadata.json`をリポジトリのルートに置くか、`SONGFINDER_DATA_DIR`で場所を指定すると動作します（[データ](docs/DATA.md)）。

### バックエンド
```bash
pip install -r requirements.txt
python app.py
```
* `http://localhost:7860`で起動します。初回起動時に埋め込みモデル（数百MB）をダウンロードします。

### フロントエンド
別のターミナルで実行します。
```bash
cd frontend
npm install
npm start
```
* `http://localhost:4200`で起動します。

### テスト
```bash
pip install -r requirements-dev.txt
pytest -q tests
```
* 検索モジュール（`search.py`）のテストです。単体テストは合成した索引で動きます。歌詞データがある場合は、1行のクエリが以前のロジックと同じ曲を選ぶかを確かめる統合テストも実行されます。

## 🖼️ 使い方

1. **検索開始：** メイン画面で**음성으로 찾기**（音声で探す）か**텍스트로 찾기**（テキストで探す）を押します。
2. **音声検索：** マイクを許可し、覚えている歌詞を5〜15秒話します。歌詞のない鼻歌は認識しません。
3. **結果と再生：** 見つかった曲と推薦曲が表示されます。Spotifyにログインすると、Webプレイヤーですぐに聴けます。
4. **プレイリスト作成：** 「이 곡들로 플레이리스트 만들기」（この曲でプレイリストを作る）を押すと、タイトルと説明を生成してSpotifyアカウントに保存します。

## 📁 構成

```
app.py                 FastAPI バックエンド（STT、検索・推薦 API、Spotify、プレイリスト文の生成）
search.py              曲の特定と推薦（SongIndex：FAISS 検索、断片の投票）
*_embeddings.npy       歌詞の行・曲・要約の埋め込み（search.py がルートから読む、Git LFS）
frontend/              Angular フロントエンド
eval/                  曲の特定の評価スクリプトと結果
tests/                 search.py のテスト
notebooks/             データ収集・前処理・タグ生成のノートブック（2025年の開発当時）
docs/                  評価の詳細、データ案内、研究開発記録、ADR
```
