# ADR-0014: README 원본은 한국어, 코드는 Apache-2.0, 노트북은 notebooks/ 로

- 상태: 채택
- 결정일: 2026-10-26

## 맥락
- 저장소 이름이 `LLM_STT_Songfinder` 에서 `RAGSTT4Lyrics` 로 바뀌었는데 README 제목은 Songfinder 였고, 이름의 "RAG" 를 설명하지 않았다.
- README 끝의 저작권 고지는 "무단 복제·배포·전송·전시 금지"였는데, LICENSE 파일은 첫 커밋(2025-08-06)부터 Apache-2.0 이다. 금지 문구는 2025-10-13 에 나중에 들어갔다. 둘이 모순된다.
- 저장소 루트에 2025년 개발 당시의 노트북 4개와 빈 `app_log.txt`(이미 .gitignore 대상)가 올라가 있었다.
- 사용자의 6개 저장소 README 를 같은 원칙으로 맞추기로 했다: 원본은 한국어, GitHub 첫 화면(README.md)은 영어.

## 결정
- README 원본은 `README_kr.md`. 영·일은 번역이고, 각 파일 맨 위 HTML 주석에 원본과 동기화 날짜를 적는다.
- 제목은 저장소 이름 + 한 줄 설명, Songfinder 는 괄호로 남긴다. 이름이 STT → Retrieval → Generation(플레이리스트 문구) 흐름이고, 곡 식별 자체는 LLM 이 아니라 임베딩 검색이라는 점을 적는다.
- **코드는 Apache-2.0 을 유지한다.** 커밋이 모두 작성자 본인 것이고 LICENSE 가 먼저 있었다. 팀 몫(URFIT 이름, 기획, 발표 자료)은 팀 "노래불러조"의 것으로 밝히고, 가사는 포함하지 않는다고 적는다.
- 노트북은 `notebooks/` 로 옮긴다(이름·내용은 그대로). `app_log.txt` 는 추적에서 뺀다. `*_embeddings.npy` 는 `search.py` 가 루트에서 읽으므로 그대로 둔다.

## 버린 대안
- 금지 문구를 유지하고 LICENSE 를 지우기: 공개 포트폴리오 저장소의 코드를 읽고 재사용할 근거가 없어지고, 이미 Apache-2.0 으로 받아 간 사람에게는 소급되지 않는다.
- 노트북 파일 이름을 영문으로 바꾸기: 개발 기록으로서의 날짜·한글 이름을 남기는 편이 낫다고 봤다.

## 남은 문제
- 옮긴 노트북의 **출력 셀에 가사 일부와 수집 로그가 남아 있다.** [ADR-0002](0002-no-lyric-text-in-outputs.md)(가사 원문을 산출물로 내보내지 않는다)와 어긋난다. 출력을 지울지는 사용자 결정으로 남긴다. 지워도 git 기록에는 남는다.
